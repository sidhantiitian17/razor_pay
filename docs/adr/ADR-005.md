# ADR-005: Seed protocol — dev, holdout, regression

## Status
Accepted

## Context
PLAN.md used a single golden seed (42) in CI. Multi-seed evaluation was a manual doc step, not a gate (D9, R10).

## Decision
Three seed sets with strict boundaries:
- **dev** (1-10): threshold tuning, prompt iteration, debugging. May influence code.
- **holdout** (101-120): all reported numbers. May **not** influence code.
- **regression** (42): golden snapshot only. Never a metric claim.

Burn protocol: if holdout results cause any code change, rotate to 201-220 and record in an ADR.

## Consequences
"We hit 92%" means "on seeds we had never run before". Holdout hygiene is enforced by a test (5.15).
